# 静态物理检查与资产任务可用性的区别

## 核心结论

当前 Pipeline 通过读取 USD 中的物理参数，可以证明：

> 物理属性已经被正确写入，并满足预设的静态规则。

但这不能进一步证明：

> 资产在指定的机器人或仿真任务中能够正确工作。

因此，静态物理检查是资产可用性的必要条件，但不是充分条件。

## 当前 Pipeline 能够验证什么

当前静态检查主要能够验证：

- 质量、摩擦和恢复系数等字段是否存在；
- 参数是否为合法的有限数值；
- 静摩擦是否不小于动摩擦；
- USD 是否包含刚体、碰撞体和物理材质；
- 物理参数是否按照 Physics Spec 正确写入；
- 碰撞类型是否满足预设的静态规则。

这些检查能够证明资产的物理描述在结构上基本正确。

## 当前 Pipeline 不能证明什么

仅仅读取物理参数，不能判断：

- 物体是否会穿透地面或其他物体；
- 物体是否会无故倾倒、漂浮或发生剧烈抖动；
- 碰撞体是否保留了容器开口等任务相关结构；
- 质量和摩擦的组合是否会产生合理的推动结果；
- 机器人是否能够抓取、推动或操作该资产；
- 资产尺度是否与真实任务相符；
- 资产是否适用于某个具体的矿业机器人任务。

即使 USD 中的物理参数完全按照设定写入，碰撞几何、尺度、质心、求解器配置和接触处理仍然可能导致仿真任务失败。

## 建议区分的资产状态

```text
static_validated
    物理描述和 USD 结构通过静态检查

task_certified
    资产在指定任务和测试条件下通过动态仿真
```

当前 Pipeline 的最终资产更适合描述为：

> statically physics-authored asset

在没有完成动态任务测试之前，不应直接描述为：

- task-usable asset；
- simulation-certified asset；
- robot-ready asset。

## 下一步需要增加的内容

应在现有静态检查之后增加：

```text
任务条件定义
    → 动态仿真测试
    → 结构化失败报告
    → 根因诊断
    → 局部修复
    → 回归测试
    → 任务认证或拒绝认证
```

这样才能把“物理参数已经写入”提升为“资产已经通过任务相关的行为验证”。
